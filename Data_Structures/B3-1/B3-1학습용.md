## Hashmap?
- 데이터를 **키(Key)와 값(Value)**의 쌍으로 묶어서 저장하는 컴퓨터 과학의 가장 대표적인 자료구조

### 특징
- 빠른 속도 : 데이터 메모리를 배열(Array)에 저장 -> key 검색 -> 해시함수 -> 해시 번호 -> 버켓 -> value값 추출
- key중복 불가 : 해시함수에서 나온 해시 번호가 같을 경우 기존 키를 덮어씌움
- 데이터 순서 보장 X : 해시 함수를 통한 해시번호를 % bucket_size 하기 때문에 데이터 순서 X

### 충돌 (Collision)
- 해시번호 % bucket_size 하는 결과값이 극단적으로 겹칠 수 있음. 이 경우 충돌이 일어남.

#### 충돌 해결하는 방법
1. 체이닝 (Chaining)
   - 같은 버킷 안에 데이터를 연결 리스트로 구조화하여 줄줄이 연결함.
   - 장점: 
     - 구현이 간단하고 직관적임.
     - bucket_size를 초과하여 데이터를 계속 저장할 수 있음.
   - 단점: 
     - 한 버킷에 데이터가 많이 몰릴 경우 속도가 O(N)으로 느려져 해시맵의 장점이 깨짐.
     - 리스트 연결을 위한 추가 메모리가 소비됨.

2. 개방 주소법 (Open Addressing)
   - 충돌 시 외부 공간을 쓰지 않고, 배열 내부의 남아있는 빈 방을 찾아 데이터를 넣음.
   - 탐사 방식:
     1. 선형 탐사: 충돌 시 바로 다음 방(+1, +2 ...) 확인. (단점: 데이터가 한 곳에 뭉치는 1차 클러스터링 발생)
     2. 제곱 탐사: 충돌 시 제곱수만큼(+1^2, +2^2 ...) 건너뛰며 확인. (단점: 초기 해시가 같으면 같이 뭉치는 2차 클러스터링 발생)
     3. 이중 해시: 2차 해시 함수를 따로 두어, 충돌 시 몇 칸씩 건너뛸지(보폭)를 키마다 다르게 개별 계산. (클러스터링 해결)

### 리해싱 (Rehashing)
- 해시맵의 공간이 일정 수준(보통 70~75%) 이상 차오르면, 버킷 크기를 약 2배로 늘리고 데이터를 재배치하는 작업.
- 원리: `새로운 해시번호 % 늘어난 bucket_size`를 다시 계산하여 모든 데이터를 새 배열로 이사시킴.
- 장점: 충돌 빈도를 낮춰 해시맵 특유의 압도적인 O(1) 성능을 유지함.
- 단점: 데이터 이사 순간에 순간적인 연산 비용(지연 시간)이 크게 발생함.


## 이중연결리스트?
- 각 노드가 데이터뿐만 아니라 **'이전 노드'**와 **'다음 노드'**의 메모리 주소를 모두 기억하고 있는 자료구조
### 노드 구조
- prev : 앞쪽 노드
- data : 실제 저장할 값
- next : 다음 노드 
> 양방향으로 자유롭게 이동 가능!!

### 장점
1. 양방향 탐색 가능
    - 뒤부터, 앞부터 검색 둘가 가능
2. 빠른 노드 삭제, 삽입, 이동
    - 노드의 주소만 알고있다면 삭제, 삽입, 이동이 빠름

### 단점
1. 메모리 낭비
    - 노드마다 주소값 하나를 더 할당해 연결리스트보다 메모리를 많이 먹음
2. 구현의 복잡성
    - 포인터가 2배로 많아 코드의 복잡성과 실수할 가능성 UP

## 힙(Heap)
- 최댓값이나 최솟값을 빠르게 찾아내기위해 고안된 완전 이진트리기반의 자로구조

### 최대 힙 (Max Heap)
- 브모 노드의 값이 자식 노드의 값보다 항상 크거나 같습니다. (루트 노드에 최댓값이 위치)

### 최소 힙
- 부모 노드의 값이 자식 노드의 값보다 항상 작거나 같습니다. (루트 노드에 최솟값이 위치)

### 특징
- 상하 관계(부모-자식)만 엄격하고 좌우 관계(형제)는 무작위인 '느슨한 정렬' 상태.
- 완전 이진 트리 특성상 배열(Array) 인덱스로 직관적 구현 가능.
- 최댓값/최솟값 조회는 O(1)이지만, 데이터를 넣거나 뽑아낸 후 구조를 재정렬(Heapify)하는 데는 O(log N)의 시간이 걸림.

### 주요 활용
- 우선순위 큐 (Priority Queue) 구현의 근간
- 힙 정렬 (Heap Sort)
- 다익스트라(Dijkstra) 최단 경로 알고리즘 등
