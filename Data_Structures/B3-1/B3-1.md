# 📋 Mini Redis 과제 요구사항 및 명령어 명세서

## 1. 과제 개요 및 목표
* **분야 / 구분:** AI/SW 기초 / 자료구조와 알고리즘
* **핵심 목표:** 내장 자료형(`dict`, `set`, `collections` 등)을 일절 사용하지 않고, 직접 구현한 핵심 자료구조를 조합하여 **LRU 메모리 방출 정책** 및 **힙 기반 TTL(만료 시간) 시스템**이 탑재된 CLI 기반 Mini Redis를 구축합니다.

---

## 2. 필수 구현 자료구조 명세
| 자료구조 | 필수 구현 메서드 및 필드 | 조건 및 핵심 로직 |
| :--- | :--- | :--- |
| **이중 연결 리스트**<br>`(dllist.py)` | • `prev`, `next`, `data` 필드<br>• `insert_front`, `insert_back`<br>• `remove_front`, `remove_back`<br>• `remove_node`, `move_to_front` | • 모든 삽입, 삭제, 이동 연산은 **$O(1)$**로 구현<br>• head 방향은 최근 사용(MRU), tail 방향은 오래된 사용(LRU)으로 관리 |
| **해시맵**<br>`(hashmap.py)` | • `put`, `get`, `remove`<br>• `contains`, `keys`, `size` | • 해시 함수 직접 설계 (예: djb2 알고리즘)<br>• 충돌 해결은 **체이닝(Chaining)** 방식으로 구현<br>• 로드 팩터(데이터 수/버킷 수)가 **0.75 초과 시 버킷 2배 확장** 및 재해싱(Rehashing) |
| **최소 힙**<br>`(minheap.py)` | • `push`, `pop`, `peek`, `size`<br>• `_heapify_up`, `_heapify_down` | • 고정 길이 배열 기반 완전 이진트리로 구현<br>• TTL 효율적 관리를 위해 **`(expire_at, key)`** 형태의 튜플 요소를 정렬 기준으로 관리 |

## 3. Mini Redis 명령어 및 출력 규격 표

| 명령어 분류 | 명령어 기본 규격 | 동작 및 핵심 규칙 | 정상 출력 예시 | 에러 및 예외 출력 예시 |
| :--- | :--- | :--- | :--- | :--- |
| **기본 데이터<br>(String 타입)** | `SET <key> <value>` | • 키와 값을 저장 (LRU 순위 최신화)<br>• 기존 키 덮어쓰기 시 **기존 TTL 초기화(삭제)**<br>• 메모리 초과 시 LRU 자동 제거 수행 | `OK` | • `(error) OOM command not allowed...`<br>• `(error) ERR wrong number...` |
| | `GET <key>` | • 키의 값을 조회<br>• **조회 성공 시에만 LRU 최신으로 갱신**<br>• 만료된 키는 먼저 삭제 후 없는 키 취급 | `"value"` | • 키가 없거나 만료된 경우: `(nil)` |
| | `DEL <key>` | • 데이터 삭제<br>• 해시맵, LRU 리스트, 힙 구조에서 **동시 영구 제거** | `(integer) 1` | • 키가 없거나 만료된 경우: `(integer) 0` |
| | `EXISTS <key>` | • 키의 존재 여부 확인 | `(integer) 1` | • 존재하지 않는 경우: `(integer) 0` |
| | `DBSIZE` | • 현재 데이터베이스에 저장된 총 키 개수 반환 | `(integer) 3` | - |
| | `KEYS` | • 전체 키 목록 배열 출력 (정렬 순서 무관) | `1) "user:1"`<br>`2) "user:2"` | • 키가 하나도 없을 때: `(empty array)` |
| **메모리 관리** | `CONFIG SET maxmemory <bytes>` | • 최대 제한 메모리 설정 (바이트 단위)<br>• `0` 입력 시 제한 없음(무제한)<br>• 설정 즉시 한도 초과 분은 LRU 자동 제거 발동 | `OK` | • 정수 파싱 실패 시:<br>`(error) ERR value is not an integer...` |
| | `INFO memory` | • 메모리 사용 통계 정보 출력<br>• `used_memory`: `Σ(len(utf8(key)) + len(utf8(value)))`<br>• `maxmemory`: 설정된 최대 용량<br>• `evicted_keys`: LRU로 강제 제거된 키 누적 수 | `used_memory:22`<br>`maxmemory:30`<br>`evicted_keys:1` | - |
| **TTL 관리** | `EXPIRE <key> <seconds>` | • 키의 만료 시간(초) 설정<br>• 초가 `0` 이하일 경우 즉시 만료 및 삭제 처리 | `(integer) 1` | • 없는 키에 설정 시: `(integer) 0`<br>• 정수 실패: `(error) ERR value is not...` |
| | `TTL <key>` | • 남은 만료 시간 조회 (소수점 올림 처리) | `(integer) 5` | • 만료 시간이 없을 때: `(integer) -1`<br>• 키가 없거나 만료 시: `(integer) -2` |

## 4. 에러 처리 표준 규격 표
사용자가 잘못된 입력을 하였을 때, 프로그램이 강제 종료되지 않고 반드시 아래의 규칙에 맞춰 에러 텍스트를 출력해야 합니다.

| 에러 원인 및 상황 | 출력 포맷 (에러 규격 문자열) |
| :--- | :--- |
| **존재하지 않거나 지원하지 않는 명령어 입력** | `(error) ERR unknown command '<cmd>'` |
| **명령어의 인자(파라미터) 개수가 올바르지 않음** | `(error) ERR wrong number of arguments for '<cmd>' command` |
| **정수형 인자가 필요한 곳에 잘못된 값을 입력** | `(error) ERR value is not an integer or out of range` |
| **새 데이터 크기가 제한 용량보다 크거나 OOM 발생** | `(error) OOM command not allowed when used_memory > 'maxmemory'` |

## 5. 공통 비즈니스 제약 사항 및 엣지 케이스
1. **지연 만료 (Lazy Deletion):** 모든 키 기반 명령어(`GET`, `DEL`, `EXISTS`, `EXPIRE`, `TTL`) 실행 직전에 해당 키가 만료되었는지 먼저 타임스탬프를 체크하고, 만료되었다면 내부적으로 완전히 삭제 후 "존재하지 않는 키" 조건으로 명령어를 처리합니다.
2. **능동 만료 (Active Expire):** `SET`, `DBSIZE`, `KEYS` 등 전체 스캔이나 갱신이 일어나는 명령어 진입 시, 최소 힙(`MinHeap`)의 `peek()`을 확인하여 현재 시간 기준으로 만료된 데이터들을 상단에서부터 연속적으로 청소합니다.
3. **단일 OOM 제한:** 저장하려는 단일 엔트리(`len(key) + len(value)`) 자체의 크기가 설정된 `maxmemory`보다 크다면, 기존 데이터를 지우지 않고 즉시 OOM 에러 메시지를 반환하며 저장을 거부합니다.
