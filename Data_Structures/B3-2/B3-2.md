# Git 커밋과 암호학적 해시, DAG 정리

---

# 1. 암호학적 해시(Cryptographic Hash)

## 정의

암호학적 해시는 **원본 데이터를 해시값만 보고 유추하거나 조작할 수 없도록 설계된 해시 함수**이다.

Git은 **SHA-1**(현재는 일부 환경에서 SHA-256도 지원)을 사용하여 커밋을 식별한다.

---

## Git에서 암호학적 해시를 사용하는 이유

### 1. 코드 무결성(Integrity) 보장

Git은 단순히 파일을 저장하는 프로그램이 아니라

- 코드의 변경 이력(History)
- 데이터의 무결성(Integrity)

을 보장해야 한다.

커밋 내용이 조금이라도 변경되면 새로운 해시가 생성되므로
변조 여부를 즉시 확인할 수 있다.

---

### 2. 코드 조작 방지

비암호학적 해시(djb2 등)는 충돌(Collision)을 인위적으로 만들 가능성이 있다.

즉,

- 악성 코드를 삽입한 뒤
- 기존과 같은 해시값을 만들어
- 정상 코드처럼 위장

할 가능성이 존재한다.

SHA-1 같은 암호학적 해시는 이러한 공격이 매우 어렵도록 설계되어 있다.

---

### 3. 눈사태 효과(Avalanche Effect)

암호학적 해시는 입력이 아주 조금만 바뀌어도 결과가 완전히 달라진다.

예)

```
hello
↓

2aae6c35...
```

```
Hello
↓

f7ff9e8b...
```

대문자 하나만 바뀌어도 결과가 완전히 달라진다.

Git은 이 성질을 이용하여

- 공백 한 칸
- 문자 하나
- 파일 하나

만 바뀌어도 새로운 커밋 ID를 만든다.

---

### 4. 전 세계에서 고유한 커밋 ID 생성

수많은 개발자가 동시에 커밋을 생성하더라도

각 커밋은 거의 중복되지 않는 고유한 ID를 가진다.

덕분에

- Branch
- Merge
- Clone

등이 안전하게 수행된다.

---

# 2. 커밋 내용이 같아도 ID가 달라지는 이유

커밋 ID는 단순히 파일 내용만으로 만들어지지 않는다.

다음 정보들이 모두 SHA-1의 입력으로 사용된다.

## 1) Timestamp

커밋한 시간

```
2026-07-23 18:30:15
```

1초만 달라도

SHA-1 결과는 완전히 달라진다.

---

## 2) Parent Commit

현재 커밋의 부모 커밋 ID도 입력에 포함된다.

예)

```
A → B → C
```

C를 만들 때

```
Parent = B
```

가 함께 저장된다.

따라서

같은 코드라도

부모가 다르면

커밋 ID도 달라진다.

---

## 3) Author / Committer

작성자의

- 이름
- 이메일

도 입력에 포함된다.

예)

```
Jaehyun
```

과

```
Kim
```

이 같은 코드를 커밋해도

작성자가 다르므로

커밋 ID도 달라진다.

---

# 3. Git 커밋 생성 과정

커밋을 만들 때 준비되는 정보는 다음과 같다.

```
message
author
timestamp
parents
```

↓

이 네 가지를 SHA-1에 입력한다.

↓

```
hash
```

를 생성한다.

↓

다음 다섯 개의 정보를 하나의 Commit Entry로 저장한다.

```
hash
message
author
timestamp
parents
```

---

## 생성 과정

```
message
author
timestamp
parents
        │
        ▼
     SHA-1
        │
        ▼
      hash
        │
        ▼
Commit Entry 생성
```

---

# 4. Commit Entry

하나의 커밋 객체는 다음과 같은 구조를 가진다.

```python
class Commit:
    hash
    message
    author
    timestamp
    parents
```

각 필드의 의미

|필드|설명|
|----|----|
|hash|SHA-1으로 생성된 커밋 ID|
|message|커밋 메시지|
|author|작성자|
|timestamp|생성 시간|
|parents|부모 커밋의 hash 목록|

---

# 5. HashMap에 저장

Git에서는

```
hash
```

가 커밋의 유일한 ID이다.

따라서

HashMap에는

```
hash → Commit Entry
```

형태로 저장하면

커밋을 매우 빠르게 찾을 수 있다.

예)

```
HashMap

A31F...
    │
    ▼
 Commit Entry

B18D...
    │
    ▼
 Commit Entry
```

Hash는 논리적으로 고유하지만

HashMap 내부에서는

버킷 충돌이 발생할 수 있다.

이 경우

**체이닝(Linked List)**

으로 해결한다.

---

# 6. DAG (Directed Acyclic Graph)

## 왜 DAG를 사용하는가?

Git은

- Branch
- Merge

를 지원해야 한다.

트리는 부모가 항상 하나뿐이다.

하지만 Merge Commit은

부모가 두 명 이상이 될 수 있다.

따라서 Git은

트리(Tree)가 아니라

**DAG(Directed Acyclic Graph)**

를 사용한다.

---

# 7. DAG란?

DAG는

- Directed
- Acyclic
- Graph

의 약자이다.

## Directed

간선에 방향이 있다.

## Acyclic

순환(Cycle)이 없다.

## Graph

노드와 간선으로 이루어진 자료구조이다.

Git에서는

커밋 하나가 노드가 된다.

```
A ← B ← C
```

---

# 8. 왜 Directed인가?

간선의 방향은

부모 관계를 의미한다.

```
C → B
```

의 의미는

```
C의 부모는 B
```

이다.

반대로

```
B → C
```

이면

```
B의 부모는 C
```

가 되어

전혀 다른 히스토리가 된다.

즉,

방향은 임의가 아니라

부모 관계를 표현한다.

---

# 9. 왜 Acyclic인가?

Git에서는

이런 구조는 가능하다.

```
A ← B ← C
```

하지만

```
A ← B ← C
↑       │
└───────┘
```

처럼

순환 구조는 만들 수 없다.

이유는

A가 자기 자신의 조상이 되기 때문이다.

즉,

시간이 거꾸로 흐르는 히스토리가 만들어지므로

Git에서는 허용하지 않는다.

---

# 10. Parents를 리스트로 저장하는 이유

Git은

부모가

- 0명
- 1명
- 2명 이상

모두 가능하다.

따라서

리스트(List)로 저장한다.

## 최초 커밋

```
parents = []
```

부모가 없다.

---

## 일반 커밋

```
A ← B
```

```
parents = [A]
```

---

## Merge Commit

```
A ← C
      \
       M
      /
B ← D
```

```
parents = [C, D]
```

Merge Commit은 부모가 두 명이다.

---

# 11. HashMap과 DAG의 관계

Git 내부에서는 두 구조를 함께 사용한다.

## ① HashMap

```
hash
    │
    ▼
Commit Entry
```

빠른 조회(O(1))를 담당한다.

---

## ② DAG

Commit Entry 안에는

```
parents
```

가 저장되어 있다.

이를 따라가면

```
현재 커밋
      │
      ▼
부모
      │
      ▼
조부모
      │
      ▼
...
```

처럼 커밋 히스토리를 탐색할 수 있다.

---

# 전체 구조

```
message
author
timestamp
parents
      │
      ▼
    SHA-1
      │
      ▼
     hash
      │
      ▼
Commit Entry
(hash, message, author,
 timestamp, parents)
      │
      ▼
HashMap
(hash → Entry)
      │
      ▼
parents를 따라 연결
      │
      ▼
DAG(Commit History)
```

---

# 핵심 요약

- Git은 커밋의 무결성과 보안을 위해 **암호학적 해시(SHA-1)** 를 사용한다.
- 커밋 ID는 **message, author, timestamp, parents** 를 SHA-1으로 계산하여 생성된다.
- 하나의 Commit Entry는 **hash, message, author, timestamp, parents** 의 다섯 필드로 구성된다.
- HashMap에는 **hash → Commit Entry** 형태로 저장하여 커밋을 빠르게 조회한다.
- Commit Entry의 **parents** 필드를 통해 다른 커밋과 연결되며, 전체 커밋 이력은 **DAG(Directed Acyclic Graph)** 구조를 이룬다.
- DAG를 사용하기 때문에 Git은 **브랜치(Branch)** 와 **병합(Merge)** 를 자연스럽게 표현할 수 있으며, 순환(Cycle)은 허용하지 않는다.


---
DAG는 "다음에 누구로 이동할지"를 알려주고,
HashMap은 "그 커밋 객체가 메모리 어디 있는지"를 빠르게 찾아주는 역할입니다
