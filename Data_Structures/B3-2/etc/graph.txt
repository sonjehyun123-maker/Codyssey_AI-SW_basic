graph.py 기능 설명

1. 전체 목적
    * mini git에서 커밋 그래프를 분석하고 탐색하는 기능을 담당한다.
    * 커밋 간 관계를 이용해 로그 순서, 조상 커밋, 경로 탐색을 제공한다.
    * git의 커밋 DAG(방향 비순환 그래프)를 단순화하여 구현한다.

2. 함수별 역할
    1. get_all_commits
        * hashmap에 저장된 모든 커밋 객체를 수집한다.
        * hashmap은 버킷 연결 리스트 형태이므로 각 버킷을 순회하며 커밋을 꺼낸다.
    2. log
        * 커밋을 위상 정렬된 순서로 반환한다.
        * 부모 커밋이 먼저 나오도록 깊이 우선 탐색(DFS)으로 순서를 생성한다.
        * git log처럼 부모 관계를 따라 커밋 히스토리를 정리하는 역할.
    3. ancestors
        * 특정 커밋에서 도달 가능한 모든 조상 커밋 해시를 찾는다.
        * 부모 링크를 따라 너비 우선 탐색(BFS)을 수행한다.
        * 시작 커밋의 모든 이전 커밋을 집합으로 반환한다.
    4. build_undirected_graph
        * 커밋과 부모 관계를 무향 그래프로 변환한다.
        * 각 커밋은 부모와 연결되고, 부모도 자식 커밋과 연결된다.
        * 이후 경로 탐색(path)에서 사용하기 위한 인접 리스트를 만든다.
    5. path
        * 두 커밋 해시 사이의 최단 경로를 찾는다.
        * 무향 그래프에서 BFS를 사용하며, 여러 최단 경로가 있을 때는 사전 순으로 가장 작은 경로를 선택한다.
        * 연결이 없으면 None을 반환한다.

3. 주요 개념
    1. 커밋 그래프
        * 커밋 객체는 hash, parents, message, author, timestamp 등을 가진다.
        * parents는 부모 커밋의 해시 목록이다.
        * 각 커밋은 부모 커밋을 향하는 방향 간선을 가진다.
        * 따라서 커밋 그래프는 원칙적으로 방향 비순환 그래프(DAG)로 보고 탐색한다.
    2. 위상 정렬(Topological Sort)
        * DAG에서 모든 간선이 부모에서 자식으로 향하도록 순서를 정하는 방법.
        * 부모가 먼저 나오고, 자식은 이후에 나오는 순서를 보장한다.
        * log 함수에서는 부모 커밋을 먼저 방문한 뒤 현재 커밋을 결과에 추가하는 방식으로 구현한다.
    3. 깊이 우선 탐색(DFS)
        * 한 노드에서 시작해 가능한 한 깊게 들어가며 방문하는 탐색 방식.
        * 재귀 호출로 자식(여기서는 부모) 노드를 계속 따라간다.
        * log 함수는 DFS 구조로 각 커밋의 부모를 먼저 방문하고, 방문이 끝난 후 결과 리스트에 추가한다.
    4. 너비 우선 탐색(BFS)
        * 시작점에서 가까운 노드부터 차례로 방문하는 탐색 방식.
        * 큐(queue)를 사용해 현재 깊이 수준을 모두 처리한 뒤 다음 수준으로 이동한다.
        * ancestors 함수에서는 시작 커밋에서 부모로 한 단계씩 올라가며 모든 조상을 찾을 때 BFS를 사용한다.
    5. 무향 그래프
        * build_undirected_graph는 부모 관계를 양쪽 방향으로 연결하여 그래프를 무향으로 만든다.
        * 이렇게 하면 두 커밋 사이의 경로를 부모 방향과 자식 방향 모두 탐색할 수 있다.
        * path 함수는 이 무향 그래프를 기반으로 최단 경로를 찾는다.
    6. 최단 경로 탐색
        * BFS는 간선 수가 가장 적은 경로를 먼저 찾기 때문에 무향 그래프에서 최단 경로 탐색에 적합하다.
        * path 함수는 BFS로 모든 가능한 경로를 탐색하고, 가장 먼저 발견된 최단 길이 경로를 수집한다.
        * 같은 길이의 경로가 여러 개 있을 때는 사전 순 정렬로 가장 작은 경로를 선택한다.

4. 사용 시 주의점
    * hashmap 내부에 모든 커밋과 부모 관계가 정상적으로 저장되어 있어야 한다.
    * path 함수는 시작 커밋과 목표 커밋이 같은 그래프에 있어야 정상 동작한다.
    * 순환 구조는 없다고 가정하고 작성되었다.
    * log 함수는 해시 충돌이나 부모 해시 누락 시 올바르게 동작하지 않을 수 있다.
    * build_undirected_graph는 부모 해시가 없는 경우에도 빈 인접 리스트를 유지해야 한다.
