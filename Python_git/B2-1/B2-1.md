
## 2. 모듈 아키텍처 및 책임 분리 (Architecture & Responsibilities)

계층화 아키텍처(Layered Architecture)를 적용하여 비즈니스 로직, 데이터 입출력, 인터페이스 및 횡단 관심사를 분리했습니다.

```
budget_app/
├── models.py       [도메인/모델 계층] : Transaction 데이터 구조 및 직렬화/역직렬화 정의
├── storage.py      [저장소 계층]       : JSONL 파일 I/O, 스트리밍(Generator), 원자적 파일 교체 및 롤백 보장
├── service.py      [서비스 계층]       : 도메인 유효성 검증, 거래 CRUD, 집계/요약, CSV import/export
├── decorators.py   [횡단 관심사]       : 오류 처리(@handle_errors), 로깅(@log_execution), 성능측정(@measure_time)
├── cli.py          [프레젠테이션/CLI]  : argparse 명령행 파싱, 대화형 콘솔 입출력 포맷팅
└── __main__.py     [진입점]           : 패키지 실행 진입점 (`python -m budget_app`)
```

### 호출 흐름 (Call Flow)
1. **User / Shell** -> `__main__.py` -> `cli.main()`
2. **CLI 계층** (`cli.py`): 인자 파싱 및 대화형 입력 수신 -> 데코레이터 적용(`@handle_errors`, `@measure_time`)
3. **서비스 계층** (`service.py`): 입력값 유효성 검증(날짜, 금액, 카테고리) 및 비즈니스 규칙 처리
4. **저장소 계층** (`storage.py`): `TransactionRepository`, `CategoryStore`, `BudgetStore`를 통해 파일 읽기/쓰기/원자적 교체
5. **모델 계층** (`models.py`): `Transaction` 객체 직렬화 및 표현

## 3. 주요 클래스 및 책임 (Class Responsibilities)

### 3.1 `Transaction` (`budget_app/models.py`)
- **책임**: 단일 거래 데이터 모델 표현 및 직렬화/역직렬화
- **인스턴스 상태**:
  - `id: str` - 고유 거래 식별자 (예: `TX-000001`)
  - `type: str` - 거래 유형 (`income` 또는 `expense`)
  - `date: str` - 거래 일자 (`YYYY-MM-DD`)
  - `amount: int` - 거래 금액 (양의 정수)
  - `category: str` - 분류 카테고리
  - `memo: str` - 선택적 메모
  - `tags: List[str]` - 선택적 태그 목록

### 3.2 `TransactionRepository` (`budget_app/storage.py`)
- **책임**: 거래 데이터(`transactions.jsonl`)의 파일 I/O, ID 자동채번, 스트리밍 조회, 원자적 덮어쓰기
- **인스턴스 상태**: `path: str` (파일 저장 절대/상대 경로)

### 3.3 `CategoryStore` (`budget_app/storage.py`)
- **책임**: 등록된 카테고리 목록(`categories.jsonl`)의 조회, 추가, 안전한 삭제 관리
- **인스턴스 상태**: `path: str`

### 3.4 `BudgetStore` (`budget_app/storage.py`)
- **책임**: 월별 예산 데이터(`budgets.jsonl`)의 저장 및 조회
- **인스턴스 상태**: `path: str`

### 3.5 `BudgetService` (`budget_app/service.py`)
- **책임**: 비즈니스 유효성 검사, 거래 검색/집계(Summary), 카테고리 무결성 검증, CSV 가져오기/내보내기 오케스트레이션
- **인스턴스 상태**:
  - `tx_repo: TransactionRepository`
  - `cat_store: CategoryStore`
  - `budget_store: BudgetStore`

## 4. 저장 포맷 (JSONL vs CSV) 비교 및 채택 근거

본 프로젝트는 내부 영속성 저장 포맷으로 **JSONL(JSON Lines)**을 채택하고, 외부 데이터 교환용으로 **CSV**를 지원합니다.

| 비교 항목 | JSONL (기본 저장소) | CSV (외부 교환용) |
| :--- | :--- | :--- |
| **타입 안정성** | 태그 배열(`List[str]`), 숫자 등 복합 구조 보존 용이 | 기본적으로 평문 문자열, 콤마 등 구분자 이스케이프 필요 |
| **추가 쓰기 (Append)** | `O(1)` - 개행 단위로 한 줄씩 추가 가능하여 빠름 | 가능하나 헤더 관리 및 다중 라인 필드 시 파싱 복잡도 증가 |
| **스트리밍 파싱** | 메모리에 전체를 올리지 않고 한 줄씩 읽는 제너레이터 구현 용이 | 전체 로딩 또는 복잡한 파서 필요 |
| **원자적 안전성** | 각 라인이 독립된 유효 JSON 문서이므로 부분 손상에 강함 | 행 내부 개행이나 인용부호 깨짐 시 전체 파일 파싱 실패 위험 |
| **외부 호환성** | 개발자/시스템 친화적 | 엑셀/스프레드시트 등 일반 사용자 도구와 호환성 우수 |

> **선택 근거**: 대용량 거래 데이터의 빠른 추가 쓰기(`append`), 스트리밍 제너레이터 기반의 메모리 절약, 태그 등 리스트 필드의 안정적인 직렬화를 위해 내부 영속 포맷으로 **JSONL**을 선택했습니다.

## 5. 원자적 파일 교체 및 장애 롤백(Rollback) 전략

거래 수정/삭제, 카테고리 정리, 예산 갱신 등 파일 전체를 다시 작성해야 하는 작업 시 데이터 무결성을 보장하기 위해 2단계 안전장치를 적용했습니다:

1. **임시 파일 작성 및 원자적 교체 (`os.replace`)**:
   - `file.jsonl.tmp`에 새 데이터를 완전히 쓴 뒤, OS 레벨의 원자적 시스템 콜인 `os.replace`로 원본 파일을 원자적으로 덮어씁니다.
   - 쓰기 도중 정전이나 강제 종료가 발생해도 원본 파일(`file.jsonl`)은 전혀 손상되지 않습니다.
2. **백업 생성 및 예외 시 자동 롤백 (Automatic Rollback on Exception)**:
   - 교체 전 원본 파일의 백업(`file.jsonl.bak`)을 생성합니다.
   - 쓰기 또는 교체 도중 예외(`Exception`)가 발생하면 임시 파일을 삭제하고 백업 파일로부터 원본을 복원합니다.
   - 정상 완료 시 백업 파일은 즉시 정리됩니다.

## 6. 데코레이터 설계 및 사용 가이드 (`budget_app/decorators.py`)

횡단 관심사(Cross-cutting Concerns)를 비즈니스 로직과 분리하여 데코레이터로 제공합니다.

| 데코레이터 | 책임 및 동작 | 적용 예시 |
| :--- | :--- | :--- |
| `@handle_errors` | 커스텀 `AppError`, `FileNotFoundError`, `ValueError` 등을 포착하여 사용자 친화적인 메시지와 해결 힌트 출력 후 정의된 종료 코드로 안전하게 종료 | 모든 CLI 진입점 함수 (`cmd_*`) |
| `@log_execution` | 함수 호출 시작 시 함수명을 표준 에러(`stderr`)로 로깅하여 실행 추적성 확보 | 주요 CUD 액션 함수 (예: `cmd_add`) |
| `@measure_time` | `time.perf_counter()`를 사용하여 함수 실행 시간을 밀리초 단위로 측정 및 출력 | 성능 모니터링이 필요한 함수 (예: `cmd_add`, `cmd_summary`) |

## 8. 예산 초과 및 알림/로그 정책

- **사용률 계산**: 지정 월의 `총 지출(expense) / 설정 예산(budget) * 100` (%)
- **초과 판정**: `총 지출 > 설정 예산`인 경우 `over_budget = True`
- **알림 및 출력 정책**:
  - `summary` 커맨드 실행 시 사용률을 소수점 1자리까지 표기
  - 예산 초과 시 즉시 명시적인 경고 메시지 `[경고] 예산을 초과했습니다!` 출력
  - CI/CD 및 모니터링 연동 시 `summary` 결과를 바탕으로 슬랙 웹훅 또는 로그 경고 레벨로 전달할 수 있도록 딕셔너리 플래그 제공

## 9. CSV Import 검증 및 부분 임포트/롤백 정책

### CSV 스키마
| column | required | 형식/설명 |
| :--- | :---: | :--- |
| date | Y | YYYY-MM-DD (날짜 유효성 검사) |
| type | Y | `income` 또는 `expense` |
| category | Y | 기존에 등록된 카테고리만 허용 |
| amount | Y | 양의 정수 |
| memo | N | 문자열 (기본값: 빈 문자열) |
| tags | N | 쉼표(`,`)로 구분된 태그 문자열 |

### 헤더 유효성 검사 & 리포트
- 파일 읽기 시작 전 헤더 행에서 필수 필드(`date`, `type`, `category`, `amount`) 존재 여부를 사전 검증합니다.
- 누락 시 작업을 중단하고 누락된 필드 목록을 사용자에게 알립니다.

### 오류 정책 (`--on-error`)
- `--on-error skip` (기본값):
  - 실패 행을 건너뛰고 나머지 정상 행은 등록합니다.
  - 건너뛴 행의 **행 번호(Line number), 원인 메시지, 실제 행 데이터 내용**을 상세 리포트로 출력합니다.
- `--on-error fail-fast`:
  - 유효하지 않은 행을 발견하는 즉시 작업을 중단하고 예외를 발생시키며, 파일에 아무런 레코드도 반영되지 않도록 원자성을 보장(전체 롤백 효과)합니다.

## 10. 대용량 데이터(100k+) 처리 분석 및 최적화 전략

### 스트리밍 처리 (`TransactionRepository.stream_all`)
- 모든 거래를 한 번에 메모리 리스트(`list`)로 올리지 않고, Python 제너레이터(`yield`)를 사용하여 **한 번에 한 줄씩** 읽습니다.
- **메모리 복잡도**: `O(1)` (10만 건 이상의 데이터도 수 MB 이하의 일정한 메모리 점유율 유지).
- `list --limit N`: 전체를 읽지 않고 `collections.deque(maxlen=limit)` 버퍼를 사용하여 최대 N건만 메모리에 보관.

### 100k 이상 확장 시 예상 병목 지점 및 개선 방안
1. **역방향 탐색 및 정렬 병목 (`search`, `summary`)**:
   - *병목*: 매번 전체 JSONL 파일을 처음부터 끝까지 순차 스캔(Full Scan, $O(N)$).
   - *개선*:
     - **월별 분할(Partitioning)**: `transactions_2024-01.jsonl` 형태로 파일 분할 저장하여 특정 월 조회 시 I/O 90% 이상 절감.
     - **인덱스 파일 구축**: 날짜(`date`) 및 카테고리(`category`) 별 파일 오프셋(offset)을 기록하는 B-Tree 또는 인덱스 맵 생성.
2. **전체 재작성 병목 (`update`, `delete`, `category remove`)**:
   - *병목*: 단 1건을 수정/삭제하더라도 전체 파일을 다시 쓰는 $O(N)$ 디스크 I/O 발생.
   - *개선*:
     - **Append-only & Tombstone(삭제 플래그) 전략**: 수정/삭제 레코드를 파일 끝에 추가 기록(Compaction은 백그라운드 주기적 수행).
3. **대량 쓰기 청크 버퍼링 (Chunked Write)**:
   - *개선*: 대량 임포트 시 라인 단위 I/O 대신 청크(예: 1,000건 단위) 버퍼를 모아 일괄 쓰기 수행.

## 12. 전체 명령 실행 예시 및 로그 스냅샷

`make all` 실행을 통해 모든 서브커맨드(카테고리 대체 삭제, CSV 검증 및 리포트 포함)의 정상 동작을 검증할 수 있으며, 전체 로그는 [`logs/test.txt`](file:///C:/Users/재현/.gemini/antigravity/scratch/Codyssey_AI-SW_basic/Python_git/B2-1/logs/test.txt)에 저장됩니다.

```bash
# 1. 카테고리 추가 및 목록
$ python3 -m budget_app category add  # salary 입력
$ python3 -m budget_app category list

# 2. 거래 추가 (add)
$ python3 -m budget_app add  # 2024-01-15, expense, food, 15000, 점심

$ python3 -m budget_app update --id TX-000001 --amount 18000 --memo "점심(수정)"

# 7. 거래 삭제 (delete)
$ python3 -m budget_app delete --id TX-000003

# 8. 카테고리 안전 삭제 (대체 옵션 지정)
$ python3 -m budget_app category remove --name food --replace-with etc

# 9. CSV 내보내기 및 가져오기 (export / import)
$ python3 -m budget_app export --out export.csv --month 2024-01
$ python3 -m budget_app import --from export.csv
$ python3 -m budget_app import --from invalid.csv --on-error skip
```
